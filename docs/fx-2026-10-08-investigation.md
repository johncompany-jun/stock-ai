# FX モデル改修調査 (2026-10-08)

## きっかけ
直近 FX メール配信の実績確認から始まり、「予測精度を上げるには外部指標が要るのでは」という議論へ。SBI口座開設の是非 → 口座より特徴量追加が効くという結論。そこから当日中に実運用整合まで一気に修正。

## 直近18トレードの実績 (改修前のライブ値)
期間: 2026-09-09〜2026-10-07、USDJPY (旧モデル: 8:30エントリー, 85分窓)
- 勝率: 13W / 5L = **72.2%**
- 累計: **+88.3 pips** / 平均 +4.9 pips/trade
- GitHub Actions の件名ログから集計 (`gh run view ... --log | grep subject=`)

ただし 18 件は小サンプル。長期 OOS で検証すると実際は 50%前後 (下記 backtest 参照) で、72% は好調な1ヶ月だったことが判明。

## 発見した3つの問題

### 問題1: ラベル窓とユーザー実運用の不整合
- モデルの TP/SL 判定窓: 8:30-9:55 JST (85分)
- ユーザー実運用: 「11:00 までに手仕舞い」(持ち越し禁止)
- → 10:30 に TP 到達した日は **実際には勝ちだがモデルラベルは中途半端な終値**
- 修正: ラベル窓を 150分 (8:30-11:00) に拡張

### 問題2: 特徴量が USDJPY 自身の値動きのみ
既存 features: entry_price, ny_delta_pips, morning_trend_bps, gotoubi_flag, dow
→ 外部指標ゼロ。日経225・DXY・米金利といった王道ドライバーを無視していた。
- 追加した特徴量: `nikkei_prev_return_bps`, `dxy_prev_return_bps`, `tnx_prev_return_bps`
- 汎用的な `external_daily (symbol, date, close)` テーブルを新設
- 新スクリプト `scripts/fx-update-external.ts` + GitHub Actions 日次 cron に組み込み

### 問題3: モデルのエントリー時刻が実運用とズレ
- モデルの学習エントリー: 8:30 JST (メール配信直後)
- **ユーザーの実エントリー: 9:00 前後** (メール見て判断してから発注)
- → 30分のズレで、別の価格から ±20pips を測ることに
- 修正: エントリー時刻を 9:00 に移行、ラベル窓を 120分 (9:00-11:00) に

## 数字で見る改善 (OOS test 260日前後、threshold=0.50)

| 段階 | モデル構成 | 勝率 | 累計 pips |
|---|---|---|---|
| 開始時点 | USDJPY only, 85分窓 | ≈50% (未測定) | — |
| ラベル窓拡張 | USDJPY only, 150分窓 | 49.6% | +36 |
| +N225 | 1外部特徴量 | 50.8% | -22 |

**最大の効き**: エントリー時刻を実運用に合わせたこと (特徴量追加より効果大)。

### ベースライン比較 (新モデル条件下)
- always LONG: 48.3% / -353p
- always SHORT: 51.9% / +364p (9:00-11:00 窓は SHORT bias あり)
- LONG except Mon: 52.4% / +18p
- **新モデル (3特徴量, th=0.50)**: 54.8% / +402p ← 全てを上回る
- 新モデル (th=0.55, 62件): 58.1% / +149p (高信頼度フィルタも機能)

## 最終モデル構成 (2026-10-08 デプロイ)

### 運用規則
| 項目 | 値 |
|---|---|
| メール配信 | 8:30 JST (US時間動きを特徴量化) |
| エントリー | **9:00 JST 前後**、手動 |
| 利確 | +20 pips 到達で即決済 |
| 損切 | -20 pips 到達で即決済 (損失キャップ) |
| タイムカット | **11:00 JST**、持ち越し禁止 |
| 目標勝率 | 10回中7回 (70%) で平均プラス |

### 特徴量 (11次元)
1. `morning_trend_bps` — 7:30-8:59 JST の USDJPY トレンド (bps)
2. `ny_delta_pips` — 前営業日 9:00 → 当日 9:00 の変化 (pips)
3. `nikkei_prev_return_bps` — 日経225 前営業日比 return (bps)
4. `dxy_prev_return_bps` — DXY 前営業日比 return (bps)
5. `tnx_prev_return_bps` — 米10年金利 前営業日比 return (bps)
6. `gotoubi_flag` — ゴトー日
7-11. `dow` one-hot (月〜金)

### モデル
- 5-seed MLP ensemble: 16→8→1 (ReLU + sigmoid, L2 + Dropout)
- 学習: 779日 (2023-01〜2026-08-10)
- kNN top10 併記 (「過去 X 営業日で今朝と似ていた日」)

### インフラ
- データ: Dukascopy minute candles + yfinance daily
- `external_daily` テーブル: ^N225, DX-Y.NYB, ^TNX の日次close
- 日次 cron: 07:00 JST (candles+externals 更新), 08:32 JST (予測メール配信)
- モデルファイル: `data/fx/model/` に git 管理

## 教訓
1. **ライブ小サンプル(18件)の72%勝率は過信禁物**。260日 OOS で51.9%、調整後54.8%が真の姿
2. **実運用と学習データの時刻ズレを放置するとベースラインから勝てない**。特徴量追加より効くことがある
3. **ユーザー実運用を正確に聞き出すことが最優先**。SL有無・エントリー時刻・タイムカット順序で全て変わる
