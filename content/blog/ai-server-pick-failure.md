このサイトは Cloudflare Workers という「無料枠から始められる超安いサーバー」で動かしています。
最初は AI 予測モデルもその上で動かすつもりでした。
でも、やってみたら動かず、作り直すことになりました。

同じことで悩む個人開発者の方の時間を節約してもらえればと思い、記録を残します。

## 当初の構想

やりたかったのはこんな構成:

1. Cloudflare Workers (= 無料サーバー) に AI モデルを置く
2. ユーザーがアクセスした瞬間に、AI がその場で予測を返す
3. データベースも Cloudflare D1 (同じく格安) で統一
4. 月額コスト 0 円 or 数ドル

AI には **TensorFlow.js** という、ブラウザや Node で動く機械学習ライブラリを使うつもりでした。
Cloudflare Workers は Node 互換の API がだいぶ使えるので、「普通に動くだろう」と思っていました。

## 動かなかった

TensorFlow.js には WebAssembly というバイナリが含まれていて、
サイズも実行時間もそれなりに食います。
Cloudflare Workers の無料枠には:

- **バンドルサイズの上限** (圧縮後 1 MB)
- **CPU 実行時間の上限** (無料枠では 10 ms、有料でも 30 秒)

という制限があり、TensorFlow.js を素直に組み込むとサイズ上限で跳ねました。

実行時間の方も、仮にサイズを削って載せても、
LSTM モデルを 1 回動かすのに 10 ms では到底終わりません。
数秒かかります。

**結論**: Cloudflare Workers は「予測を保存して返す」のには最高だが、
「AI を動かす」のには向いていない。

## どう作り直したか

「AI を動かす場所」と「結果を見せる場所」を分けました。

| 役割 | 使ったもの |
|---|---|
| AI の学習と推論 | GitHub Actions (毎日自動実行) |
| 予測結果の保存 | Cloudflare D1 |
| 結果の表示 | Cloudflare Workers + Hono (SSR) |

GitHub Actions には **1 ヶ月 2,000 分の無料枠** があり、
AI の学習と毎日 1 回の推論なら十分収まります。
推論結果だけを Cloudflare D1 に書き込み、
Cloudflare Workers からはそれを読んで表示するだけ。
これなら Workers の 10 ms 制限も余裕で守れます。

## 月額コスト

結果的に、

- GitHub Actions: 無料
- Cloudflare D1: 無料枠内
- Cloudflare Workers Paid: **$5 / 月** (無料枠でも動きますが、安定運用のため有料化)
- ドメイン: 年 1,500 円くらい

合計 **月額 1,000 円いかない** で、個人の投資 AI サイトが運営できています。

## 教訓

無料枠を主役にする設計は、途中で制限に当たると全部ひっくり返します。
**「どのレイヤーで何をするか」** を最初に 1 枚絵で描いて、
各レイヤーの上限と実際の処理の重さを突き合わせるのがおすすめです。

今回は 「AI の推論を Workers でやる」 が無理ゲーだったので、
GitHub Actions という「毎日動かせる無料サーバー」に逃がしました。
一般化すると、

- **即応性が要らない処理** は GitHub Actions / Cron に逃がす
- **読み取りだけの軽い処理** は Workers に残す
- **データは安い DB** (Cloudflare D1) に保管

という切り分けができれば、個人開発の投資 AI サイトは月数百円で回せます。

## 他に試して諦めたもの

参考までに、同じく諦めたもの:

- **Workers 上での Puppeteer** (Yahoo Finance スクレイピング用) → Chromium が重すぎた
- **Workers 上での大量 CSV パース** → メモリ食いすぎでタイムアウト

結論、Cloudflare Workers は「静的っぽいレスポンスを超速で返す」のが得意で、
「計算を頑張らせる」のは向きません。
これを最初に腹落ちできていれば、2 日くらい時間を節約できました。

同じ失敗を避けていただくためのメモとして。
