このサイトは Cloudflare Workers + D1 (Cloudflare のマネージド SQLite) で動いています。
個人開発のツールとして運営していて、
**DB 本体のコストは月 $0** (無料枠内) で収まっています。

「個人開発で DB を持ちたいけど、月数ドルも払いたくない」
という方向けに、D1 の無料枠の使い方と、
課金に切り替えるべきタイミングをまとめます。

## 結論 - D1 は個人開発の DB として現時点ベスト

Cloudflare D1 は 2024 年に GA (一般提供) になった SQLite ベースのマネージド DB です。

無料枠が広く、Workers と同じ会社のサービスなので内部通信が速い。
個人開発ツールの DB として、2026 年 11 月時点では一番無料枠が使いやすいサービスです。

## D1 の無料枠 (2026 年 11 月時点)

Cloudflare 無料プランの D1 制限:

| 項目 | 無料枠 |
|---|---|
| 作成できる DB 数 | 10 個 |
| 1 DB あたりの最大容量 | 500 MB |
| 1 日の読み取り行数 | **500 万行** |
| 1 日の書き込み行数 | **100,000 行** |
| 1 日のストレージ | 5 GB (累積) |

個人開発ツールで一番カツカツになるのは **書き込み 100,000 行 / 日** の上限です。
読み取りは 500 万行もあるので、個人運営なら絶対に届きません。

## このサイトの実際の使用量 (参考)

このサイト (stock-ai) で保持している主なテーブル:

| テーブル | 役割 | 行数 (概算) | 日次書き込み |
|---|---|---|---|
| `candles` | 日足価格 | 約 100 万行 | 3,000 行 |
| `stocks` | 銘柄マスタ | 約 4,000 行 | 0 行 |
| `patterns` | 検出パターン | 約 50,000 行 | 20-30 行 |
| `fx_features` | FX 特徴量 | 約 800 行 | 1 行 |
| `fx_predictions` | FX 予測ログ | 約 300 行 | 1 行 |

日次の書き込みは合計 **3,000-5,000 行**。
無料枠 100,000 行の **5% 程度** しか使っていません。

このサイトは Cloudflare Workers Paid プラン ($5/月) に加入していますが、
これは **CPU 時間の上限を増やすため** であって、D1 のコストは $0 です
([Cloudflare Workers Paid への切り替え経緯](/blog/monthly-cost-breakdown))。

## D1 が合う / 合わないワークロード

### 合うワークロード

- 1 日の書き込み行数が 10 万未満
- 1 クエリでの処理行数が数千行以内
- 複雑な集計より「ID で引く」「シンプルな WHERE」が主
- データの地域局在性が許容される (= レプリカは片方の大陸)

### 合わないワークロード

- リアルタイム分析 / BI
- 日次書き込みが数百万行
- 1 クエリで数百万行をスキャン
- 複数地域での同時書き込みが頻発

個人開発ツールなら、ほぼ 100% が「合うワークロード」側です。

## 他候補との比較

### Supabase (PostgreSQL マネージド)

- 無料枠: 500 MB、月 50,000 MAU
- **強み**: PostgreSQL の機能がそのまま使える (拡張・JSON・全文検索)
- **弱み**: 1 週間アクセスが無いとプロジェクトが pause される (= 無料枠ハック対策)

個人開発で「1 日 1 回 cron で書く」ような用途だと、
Supabase の pause が邪魔になることがあります。
D1 なら pause しません。

### Neon (サーバーレス PostgreSQL)

- 無料枠: 0.5 GB、1 プロジェクト
- **強み**: PostgreSQL 完全互換、ブランチ機能 (Git みたいに DB をブランチできる)
- **弱み**: Cloudflare Workers との接続はちょっと手間 (@neondatabase/serverless 必須)

Vercel や Fly.io で動かすなら Neon は良い選択。
Cloudflare Workers で動かすなら D1 の方がシームレス。

### Turso (libSQL = SQLite のマネージド)

- 無料枠: 500 MB、9 GB/月の読み取り
- **強み**: SQLite 互換、エッジレプリケーション
- **弱み**: Cloudflare 内部ではないので遅延が増える

Turso も良いが、Cloudflare Workers で動かす前提なら D1 と同じ会社の方が速い。

## 課金 (Workers Paid) に切り替える判断ポイント

無料枠から Workers Paid ($5/月) に切り替えるべきタイミング:

### 1. CPU 時間が 10ms を超えるリクエストが増えた

無料枠の Workers は **1 リクエストあたり 10ms の CPU 時間** 制限があります。
D1 にアクセスする Hono アプリは、10ms に収まることが多いですが、
機械学習の推論などが入ると 50-100ms くらい使います。

### 2. D1 書き込みが 100,000 行 / 日に近づいた

Paid プランでは書き込み 500 万行 / 日 まで拡張されます。

### 3. Durable Objects を使いたくなった

WebSocket や同時接続管理には Durable Objects が必要で、
これは Paid プラン限定機能です。

$5/月を払うタイミングは「DB 容量が足りない」ではなく、
**「Workers の CPU 時間 or Durable Objects が必要」** のケースが多いです。

## このサイトの技術構成

参考までに、このサイトの技術スタック:

- **ランタイム**: Cloudflare Workers (Paid $5/月)
- **ルーティング**: Hono (TypeScript の軽量 Web フレームワーク)
- **DB**: Cloudflare D1 (SQLite ベース、無料枠内)
- **メール**: Resend (月 3,000 通まで無料)
- **デプロイ**: Wrangler + GitHub Actions
- **データ取得**: GitHub Actions (cron で日次実行、yfinance + Dukascopy)
- **AI 推論**: GitHub Actions 内で TensorFlow.js

月額コスト合計は Workers Paid $5 + ドメイン代 $1-2 の **月 $6-7**。
サイト詳細は [このサイトはどう動いているか](/blog/how-this-site-is-built) にまとめています。

## 無料枠のまま運用を続けるコツ

Workers Paid を払わずに完全 $0 で続けたい場合のコツ:

### 1. CPU 時間を軽くする

Hono + D1 のクエリなら、リクエスト 1 回あたり 5-10ms に収められます。
10ms の無料枠に収めるには:

- 複雑な集計はクエリで済ませる (SQL で処理 = CPU 時間に入らない)
- 画像処理などの重い処理はクライアント側で

### 2. cron 系の処理を Workers ではなく GitHub Actions で

日次のデータ取得 / 学習などは、GitHub Actions の月 2,000 分無料枠を使う。
無料枠の Workers Cron は制約が多いので、
重めの定期処理は GitHub Actions に逃がす方が楽です。

このサイトでも日次 cron は全部 GitHub Actions 側で動かしています。

### 3. 書き込みをバッチ化

1 件ずつ INSERT すると書き込みカウントがかさみます。
100 件まとめて INSERT (= BULK) に変えれば、書き込み行数は同じでも
Durable Objects などの制約が緩くなります。

## まとめ

- Cloudflare D1 + Workers で、個人開発ツールの DB コストは月 $0 に収まる
- 無料枠は読み取り 500 万行 / 書き込み 10 万行 / 日と潤沢
- Paid $5/月に切り替えるのは「DB 容量足りない」ではなく「CPU 時間 / Durable Objects」の判断
- cron 系の重い処理は GitHub Actions に逃がすのが個人開発のコツ
- 他候補 (Supabase / Neon / Turso) もそれぞれ良いが、Workers 前提なら D1 が最適
