ドル円 (USDJPY) の寄付方向を予測する FX モデルを個人で構築しました。
2026-08 頃から試行錯誤し、現時点で 261日の out-of-sample (OOS) 検証で:

- **勝率 54.8%**
- **累計 +402 pips** (平均 +1.54 pips/trade)

という数字が出ています。
過度に美しい数字ではないですが、「個人でもここまでは行ける」ラインの参考値として、
構成とハマりどころを公開します。

## モデル構成

**データ:**

- 分足データ: Dukascopy の tick-level 3年分
- 日足外部データ: yfinance 経由で 日経平均 (`^N225`) / ドルインデックス (`DX-Y.NYB`) / 米国10年債 (`^TNX`)

**特徴量 (入力):**

| 名前 | 内容 |
|---|---|
| entry_price | 当日 9:00 寄付価格 |
| ny_delta_pips | 前日 NY クローズと当日寄付の差分 (pips) |
| morning_trend_bps | 当日 8:00 - 9:00 の方向性 (bps) |
| gotoubi_flag | 五十日 (ごとおび) フラグ |
| dow | 曜日 |
| n225_prev_return_bps | 前日 日経平均リターン (bps) |
| dxy_prev_return_bps | 前日 ドルインデックスリターン (bps) |
| tnx_prev_return_bps | 前日 米国 10年金利リターン (bps) |

ゴトー日 (5の倍数日) は実需の USDJPY 買いが入りやすい、というアノマリーを明示的に特徴量化しています。

**モデル:**

- 5-seed MLP アンサンブル (16 → 8 → 1、ReLU + sigmoid、L2 + Dropout)
- kNN top-10 で過去類似日の勝敗を集計 (サイト上に表示)

LLM 的に大きなモデルではなく、小さい MLP の 5 回アンサンブルで出力を平均化しています。
TensorFlow.js で Cloudflare Workers 上では動かないので、GitHub Actions で推論しています。

## 検証ルール (エントリー/エグジット)

- **エントリー**: 9:00 JST (= 00:00 UTC) の寄付足
- **利確**:
  - LONG: TP **+25 pips**
  - SHORT: TP **+30 pips**
- **損切り**: 共通 SL **-20 pips**
- **強制手仕舞い**: 11:00 JST の時点でまだ生きていればクローズ (持ち越さない)

LONG と SHORT で TP を変える「非対称 R:R」になっています。
後述するように、実運用のサンプル分布から事後的にチューニングした結果です。

## バックテスト結果 (OOS 261日)

| しきい値 | 件数 | 勝率 | 累計 pips | 1トレードあたり |
|---|---|---|---|---|
| 確率 0.50 (全部) | 261 | **54.8%** | **+402** | +1.54 |
| 確率 0.55 以上 | 62 | **58.1%** | **+149** | +2.40 |

「迷った日は見送って、確率 0.55 以上の日だけ入る」とすると、
件数は 1/4 に減りますが 1トレードあたりの期待値は改善します。
運用スタイル (ロット増やしたい派 / 高確度日だけ選びたい派) で選べる状態です。

## ハマりどころ 1 - TP を対称にしていたら SHORT の数字しか出なかった

当初は TP ±20 pips (対称) でした。
しかし 28 トレードの実運用サンプルで:

- LONG 側の TP ヒット: ほとんどなし (平均 +1.6 pips)
- SHORT 側の TP ヒット: 良好 (平均 +72.6 pips)

という偏りがあり、「ドル円は売りの方が効く日が多い」というアノマリー (リスクオフ時の円買い) が
短時間足でも観測できることが分かりました。

このため TP を **+30/-20** (SHORT のみ利伸ばし) → さらに **LONG+25/SHORT+30 の非対称** に調整。
LONG を +25 まで下げた理由は、LONG 側は +25 到達率が +30 到達率より明確に高く、
平均値では +25 で止める方が trade あたりの期待値が上がったためです。

## ハマりどころ 2 - 「低ボラ日はスキップ」が逆効果だった

連敗期に「寄付前のボラが低い日 (= レンジ相場濃厚) はスキップした方が良いのでは」と疑い、
前日 ATR + 当日の morning_trend (8-9時) を使った低ボラ日フィルタを検討しました。

**結果:** 781日の履歴で検証したところ、
意外にも「朝の動きが一番静かな日 (morning_trend < 3bps)」が最も期待値が高い (+4.59 pips/trade) というデータに。
フィルタの実装は見送りました。

**ここで学んだこと:** 「体感で負けが続いている時」は変数の 1つ (ルール) を変えたくなりますが、
バーレベル (分足単位) で見直すと、変更前のルールでも TP 到達しなかっただけ (= 単に凪いだ日が続いただけ) のことが多いです。
短期サンプルの変動と、ルールの効き目は分離して評価する必要があります。

## 実運用の体感 (2026-10月)

実運用的なサンプリング 28トレードで:

- 勝率 70%
- 累計 +109 pips
- 最大 DD 約 2%

という結果が出ていますが、これは **期間が良かっただけ** と現時点では解釈しています。
バックテスト上の勝率は 51.9% なので、「70% が続く」と仮定するのは危険です。

実運用のサンプルが N=50 を超える頃 (2026-12月前後) に、改めて数字を照合する予定です。

## インフラ構成

参考までに、個人運営の構成:

- **データ取得**: GitHub Actions (`daily-fx-candles.yml` 毎日 UTC 01:00) で Dukascopy + yfinance から取得して Cloudflare D1 に書き込み
- **モデル推論**: GitHub Actions (`daily-fx-signal.yml` 毎日 UTC 00:05) で TFJS 推論、結果を D1 保存
- **公開**: Cloudflare Workers + Hono で `/fx/` SSR ページ配信
- **通知**: Resend 経由で登録者にメール配信 (現在は手動運用、将来的に自動化予定)

月額コストは Cloudflare Workers Paid ($5) + ドメイン代くらい。
個人の実験としては十分 scalable です。
